# 彩虹塔罗 V3.0.1 — 安装与玩法

本版改为 **Paper 插件 + 客户端资源包**，目标版本为 Paper / Minecraft 26.3、Java 25。新交互不再由旧数据包驱动。

## 3.0.1 更新与升级测试

- 未启用资源包时，卡牌、卡包、卡盒和卡箱均显示原版纸张，保留名称、星级和效果说明；启用本版资源包后显示彩虹模型。普通纸张保持原版外观。
- 插件与资源包需要一起更新：旧资源包不含新的纸张选择规则，搭配新插件时会显示纸张。
- 修复创造模式升级没有提示的问题。创造背包仍不执行合成，拿取卡牌时会提示切换生存或冒险模式；五星已经满级。
- 移除无效的拖拽合成分支，避免原版恢复鼠标物品时保留材料。升级采用左键拿起，再左键点击目标卡的操作。
- `/tarot card` 每次发放一张，末尾不接受额外“数量”参数；错误参数现在会明确报出用法。
- 旧 V3 卡牌和包装在玩家上线或执行 `/tarot migrate` 后改用纸张回退模型，保留卡名、星级、数量和自定义显示名称。箱子中的旧物品取到背包后再执行该命令。

从 3.0.0 更新时：正常停服，把 `plugins/TarotRainbow-3.0.0.jar` 移出 plugins 目录备份，放入 `TarotRainbow-3.0.1.jar` 后启动；保留 `plugins/TarotRainbow` 数据文件夹。客户端移除旧版资源包并启用 `tarot_resources_rainbow_v3_0_1.zip`。未安装资源包的玩家会看到纸张。

管理员测试示例（玩家名按实际替换）：

```
/gamemode survival Rincho
/tarot card Rincho 22 1
/tarot card Rincho 22 1
```

打开背包，左键拿起一张一星世界并松开鼠标，再左键点击另一张一星世界，结果应为一张二星世界，鼠标上的材料清空。

新增回归已在真实 Paper 26.3 上通过两次：使用模拟玩家和背包视图，经插件注册的事件入口验证92组合成（22张卡的1～4星及冒险模式）、背包/快捷栏、左/右键、满背包、满级与不匹配拒绝、创造模式提示和不消耗材料。使用真实物品元数据与库存存储；这不等同于连接真人客户端操作。

## 安装与旧版迁移

1. 在旧数据包仍启用时，执行 `/function tarot:disable`，然后正常停服。若已经移除旧包，可跳过该命令；插件会在玩家上线时清理旧塔罗属性。
2. 将世界 `datapacks` 文件夹里的旧 `tarot_26_3*.zip` 或对应解压文件夹移到该目录外备份。不要同时运行旧塔罗数据包和新插件。
3. 把 `TarotRainbow-3.0.1.jar` 放进服务端 `plugins` 文件夹，启动服务器。不要使用 Bukkit/Paper 的 `/reload` 热重载插件。
4. 客户端把 `tarot_resources_rainbow_v3_0_1.zip` 放进当前游戏实例的 `resourcepacks` 文件夹，在“选项 → 资源包”中把它移到右侧启用，关闭旧黑金资源包。
5. 旧卡牌和旧包装会在玩家上线、关闭背包、使用副手卡牌时更新为新版。也可以手动执行 `/tarot migrate`。箱子里的旧卡取出后执行该命令即可。

本次没有修改或部署到现有 E 盘服务器。首次安装插件需要重启服务器；资源包不需要客户端模组。

## 操作

- **激活**：卡牌放副手，按住潜行，再右键空气、方块或实体。只按潜行不会激活。
- **拆包装**：卡包、盒或箱放副手，潜行＋右键。
- **升级**：在生存或冒险模式下打开背包，左键拿起一张卡并松开鼠标，再左键点击另一张同名、同星级卡。两张合为一张高一星卡，最高五星；跨牌名、跨星级不合成。创造模式禁止合成，避免客户端创造物品操作造成复制。
- **卡片描述**：明确列出实际属性增益、倍率、激活方式、效果期限和换卡限制。
- **查看状态**：`/tarot status`，显示当前卡牌、星级、效果数值、剩余期限和换卡倒计时。

激活后卡牌不消耗，可从副手移走；当前效果仍持续。换牌指激活另一张牌，而不是禁止移动背包物品。升级不会立即改变正在生效的星级，重新激活才会使用新星级。

## 时间规则

激活时开始计算：效果持续现实 **24 小时**，前 **30 分钟**不能换牌或再次激活。30 分钟后再次激活会替换旧效果，并重新开始新的24小时和30分钟。

离线、服务器关闭、死亡和重登都不会重置绝对截止时间。死亡后复活会恢复未到期效果。星级提升只增加效果强度；按本次新规则，各级持续时间和换牌锁定时间相同，取代旧版数秒持续和技能冷却。

默认配置保存在 `plugins/TarotRainbow/config.yml`：`duration-seconds: 86400`、`switch-lock-seconds: 1800`。修改后正常重启；已经激活的截止时间不追溯更改。

## 背包满保护

所有奖励先在内存中计算完整存放方案，确认能装下后才消耗包装。空间不足时没有卡牌发放，也不消耗包装；不会把奖励丢到地面。

- 卡牌不可堆叠，开包需要主背包/快捷栏合计 **5 个空格**，副手腾出的格子不计算。
- 包装可堆叠至64；拆盒获得8包，拆箱获得48盒，会先利用现有同类包装堆叠空间。
- 管理员发放同样执行完整容量检查；装不下则全部拒绝，不会出现只发一部分。
- 合成结果直接替换目标卡所在格，并清空鼠标上的材料卡，不需要额外空格。

这能阻止后续溢出丢失；此前已经消失的物品无法自动恢复，需要管理员按实际损失补发。

## 彩虹牌面与状态栏

22张独立彩虹像素插画、110个卡牌星级模型、3种包装、1个通用塔罗状态图标。

|稀有度|外边框|
|---|---|
|R|红|
|SR|橙|
|SSR|黄|
|SP|绿|
|UR|紫|

|星级|内边框和星星|
|---|---|
|1星|红|
|2星|黄|
|3星|青|
|4星|蓝|
|5星|紫|

资源包使用模型边框和可数的1～5颗像素星，不只是更换物品名称。发动时播放彩虹粒子环和音效，升级和开包也有提示。

背包状态栏复用原版“幸运”状态的**客户端显示**，显示通用塔罗图标和原版倒计时，不给服务器上的玩家增加药水幸运属性。实际能力仍由22张卡各自的属性组成，见卡片描述。资源包会全局替换原版幸运图标，因此真正的幸运药水也用该图标，状态名称仍是原版“幸运”。

原版不支持同一种状态同时显示两行。因此有真正的幸运药水时优先保留药水图标及其时间，塔罗时间通过行动栏和 `/tarot status` 显示。此方案不提供22张牌各自不同的状态图标。

## 抽卡与包装

22张牌固定稀有度；均从1星开始，两张同名同星升一级，升到5星累计需要16张1星同名卡。

每包5张，4个普通位＋1个SR或以上保底位；允许同包重复，同稀有度内各卡等概率。

|稀有度|普通位概率|保底位概率|
|---|---:|---:|
|R|80%|0%|
|SR|18%|94%|
|SSR|1.7%|5%|
|SP|0.25%|0.9%|
|UR|0.05%|0.1%|

一盒8包＝40张；一箱48盒＝384包＝1920张。没有额外盒保底或箱保底。幸运属性不会提高卡包出率。

## 管理员命令

需要OP或 `tarot.admin` 权限。以下“玩家名”替换为在线玩家真实名称。

```
/tarot give 玩家名 pack 1
/tarot give 玩家名 box 1
/tarot give 玩家名 case 1
/tarot card 玩家名 8 3
/tarot clear 玩家名
```

`card` 后两个数字分别是牌编号1～22、星级1～5，上例为3星战车；`clear` 会清除该玩家当前塔罗效果和换牌锁定。
